## 1. Migration Sequence & Strategic Rationale

The migration sequence follows a strict dependency order:
```text
WAVE A: Hygiene, Identity & Canonical Source Integrity (P0)
       ↓
WAVE B: Ontology, Registry & Capability Ownership Stabilization (P1)
       ↓
WAVE C: Shared Protocols & Duplicated Capability Consolidation (P1)
       ↓
WAVE D: Domain Intellectual Architecture & Epistemic Safeguards (P2)
       ↓
WAVE E: Dissemination Architecture & Public Scholarship (P2)
       ↓
WAVE F: Physical Tree Harmonization & Client Packaging (P3)
```

### Strategic Principles
1. **Never expand capabilities on an ambiguous foundation:** Do not create new skills (e.g., `political-economy-research`) until repository identity, canonical source trees, and capability ownership are strictly stabilized.
2. **Decouple logical ownership from physical file moves:** Client runners (Antigravity, Claude Code, Codex) depend on current paths. Reclassify logically first through registries and routing rules. Physical moves occur only in the final wave with automated discovery tests.
3. **Stop Conditions are Binding:** Each wave has explicit, measurable exit criteria and STOP conditions. If a STOP condition is triggered, all progress halts until human review resolves the blocker.
